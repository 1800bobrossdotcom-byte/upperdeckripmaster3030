# models/cc0 — CC0-lineage asset set

**This is the file that answers "where did this come from".**

Everything in this directory is **generated by scripts in this repo**. No third-party image, mesh,
texture or model file was committed — not one. The geometry comes from
`scripts/blender/build-cc0-props.py` and `scripts/blender/build-cc0-chars.py`; the textures and
`skins.json` come from `scripts/build-cc0.mjs`; the previews come from
`scripts/blender/build-cc0-preview.py`. Delete the whole directory and `npm run cc0 -- --preview`
rebuilds it byte-for-byte.

That is the point, and it is the same argument `scripts/blender/kit.py` makes about levels: **if
every triangle is generated by a script we wrote, the geometry is unambiguously ours.** This
project mints on-chain, where a licensing mistake is permanent — so "we studied it and rebuilt it"
is a materially different position from "we downloaded it and changed it", and only the first one
is safe to put inside a token.

**Licence evidence for every source named below: [`docs/CC0-SOURCES.md`](../../docs/CC0-SOURCES.md).**
Only sources graded **VERIFIED** or **ATTESTED** there were allowed to inform anything here.

---

## What "inspired by" means here, precisely

A palette is not copyrightable. Nor is a proportion, a construction rule, a dither matrix, or the
observation that an artist never uses white. **A character is.** So the line this set holds is:

| taken | not taken |
| --- | --- |
| measured colour statistics | any image, or any part of one |
| body proportions and mass distribution | faces, features, traits, marks — **no face is modelled at all** |
| construction rules (strict grid, flat fill, 1-bit dither, 4-colour limit) | compositions |
| FX vocabulary (scanline, slice-offset, halftone, ordered dither) | any project's name, logo or wordmark |

Two shapes were deliberately **not** built, and the reason is the same in both cases — they are
marks, and CC0 waives copyright but never trademark:

- **No Nouns noggles.** The eyewear is the Nouns identity. The palette is dedicated; the mark
  still functions as a mark.
- **No Pepe, anywhere.** Rare Pepe and Fake Rares are the artist's own home scene and it is still
  a no: there is no blanket dedication over those directories, and the underlying character is
  Matt Furie's and actively enforced. The lineage lives in this project as *form* — the card, the
  rip, the pull — not as pixels.

Nothing here impersonates another project or presents itself as an official asset of one.

## The geometry

### `cc0-props.glb` — 9 objects, 2,706 tris, 151 KB

Authored base-at-0 and ~1 unit tall, the same contract `models/dogfight.glb`'s props use: the
loader normalises height to exactly 1, so what survives is the proportion, not the size. One
object per prop, because the renderers draw a prop as a single VBO with a single tint.

| object | tris | lineage (all VERIFIED) | what was actually taken |
| --- | --- | --- | --- |
| `prop_totem` | 132 | **Nouns** | Strict-grid stacking: every stage is a whole number of 1/32 cells and either is or is not wider than the one below. The 2-D pixel rule — a pixel is on or off — pushed into a third axis. Deliberately asymmetric so it has a front. |
| `prop_slice` | 324 | **XCOPY** | Datamosh in geometry. 26 horizontal bands, a minority of which tear sideways by a *quantised* offset — a block copied from the wrong address, which is what datamosh actually is. The intermittence is the signature; a uniform shear is just a skew. |
| `prop_scanbar` | 252 | **XCOPY** | The scanline as architecture. Bar spacing ramps geometrically, ~12:1 from base to top, with the bar thickness tracking the gap so the *duty cycle* holds while the frequency falls. |
| `prop_lump` | 700 | **goblintown** | Committed asymmetry. Overlapping jittered ellipsoids, nothing symmetrical, mass sagging to one side. **Not a creature** — a growth/boulder prop. The attitude transfers; a face would have been a derivative character. |
| `prop_slate` | 96 | **Loot** | A standing slab with an **empty** recessed panel. Loot's move is that it ships no image and leaves the picture to you; the recess is the asset. No Loot item names are used — the item names are the only authored part of Loot. |
| `prop_dither` | 420 | **Anonymice** | An 8×8 Bayer field in relief on one face, thresholded against a height ramp. A stud is present or absent; there is no half stud, because the whole idea is that tone comes from pattern, not from value. |
| `env_deck` | 588 | **Anonymice / Blitmap** | A 1×1 modular floor tile whose border dissolves into an ordered-dither fringe instead of ending on a hard edge — the 1-bit trick for faking a soft edge with no greys available, which also hides the repeat. |
| `env_bars` | 180 | **Nouns** | A wall of vertical bars at quantised depths. Bars rather than a flat wall because Section 9's cover model wants silhouettes you can peek between. |
| `env_gate` | 156 | **Nouns / Blitmap** | An octagonal threshold ring. Octagonal on purpose: a 24-sided torus next to a 32-grid totem looks like it came from a different game. |

### The fighter bodies — SEVEN of them, 15 parts each

Drop-in bodies for NEON RONIN's rigid-part rig (the `.glb`) and for Section 9's skinned operatives
(the `.skn` baked from it). Part names are matched by `js/ronin3d.js`'s `JOINTMAP`; the IK skeleton

**Every one of them is one line in `SPECS` in `scripts/blender/build-cc0-chars.py`.** That is the
whole design: one builder, one skeleton, one set of numbers per body — read a column top to bottom
and you can predict the fighter before you render it.

### The three construction operators

The first set differs only in the numbers, which is honest but limited: a proportion study can say
"the head is bigger", it cannot say "the artist's move is that the image is mis-registered". So the
builder gained three optional operators, applied to a part's finished vertices before export. Each
one **is** a construction rule taken from a source — and a construction rule is not copyrightable,
which is precisely why it transfers and a traced character does not.

| operator | source | what it does |
| --- | --- | --- |
| `tear=` | **XCOPY** | Cuts the part into horizontal bands and shifts a **minority** of them sideways by a **quantised** amount. Same rule as `prop_slice`. The intermittence is the signature: a uniform shear is a skew, and a skew reads as a mistake rather than as corruption. ⚑ Hashed on the **band index alone**, with no per-part salt, so one tear cuts across the whole figure at one height — per-part noise would just look broken. |
| `key=` | **Darkfarms** | A raised belt at every mass's equator. 21.4% of every SMOWLz token is pure-black keyline around a flat fill, and a flat fill needs an **edge** to read at all. In 2-D that edge is a stroke; the 3-D equivalent of a stroke is a ridge that catches the key light. |
| `quant=` | **Nouns** | Snaps every vertex to a lattice. The 2-D rule is that a pixel is on or off; in three axes that is a vertex on a lattice point or not at all. |

Two implementation notes that are load-bearing rather than incidental:

- ⚠ **`quant` must use a step that divides 1.0 exactly** — 1/32 here. The sole sits at z=0 and the
  crown at z=1.0, both of which are lattice points under 1/32, so the height contract survives the
  snap untouched. At 1/30 it would not, and the build would fail rather than ship a body whose
  joints had all quietly shifted.
- ⚠ **`tear` runs before `quant`, and only that order works.** `tear` shifts in x, so quantising
  afterwards keeps a torn body on the lattice; tearing a quantised body by an offset that is not a
  lattice multiple would take it straight back off again.

`seg`/`rings` in a spec are **caps, not replacements** — every authored density stays what it was
unless a body asks for something coarser. That is what makes the first three bodies come out
byte-identical to what already shipped, which matters: `models/cc0-*.skn` are baked from these
GLBs, and a silent geometry change would invalidate every measured number below at once.

### The skinned bodies — `models/*.skn`, and the bake command

⚑ **The bake is part of `npm run cc0` now.** This is a direct response to the most expensive lesson
in `models/README.md`: nobody wrote down how `oni.skn` and `ronin.skn` were decimated, so for
months no asset change could be compared to anything and task #77's fix could not be verified. A
command recorded in a markdown file is a command that drifts; a command in the build cannot.

```
node scripts/bake-fighter.mjs models/cc0/<file>.glb <tmp>.obj --detail 2.5 --skin models/<file>.skn
```

**`--detail 2.5` is reproduced, not assumed.** The three already-shipped `.skn` files were re-baked
at this setting and came out **byte-identical**, which is how we know 2.5 is *the* number rather
than a number that looks close. `npm run cc0 -- --no-skin` skips the step.

Measured with `npm run stretch` — arms swung 55°, legs 35°, the same pose for every row:

| --- | --- | --- | --- | --- | --- | --- |
| `cc0-mosh` | BAD SIGNAL | 954 | 160,568 B | **1.8×** | 0 | **0** |
| `cc0-cel` | HEAVY LINE | 1,040 | 175,016 B | **2.9×** | 0 | **0** |
| `rip-mascot` | PRIZE MASCOT | 1,232 | 207,272 B | **3.1×** | 2 | **0** |
| `cc0-lank` | LONG ODDS | 994 | 167,288 B | 3.3× | 6 | **0** |

**BAD SIGNAL and HEAVY LINE are the two best-behaved bodies in the repo** — better than `oni`, the
best of the imported family — and the seven generated bodies together are **1.25 MB**, less than
two imported ones. The roster is no longer trading size against quality.

⚠ **Read the columns against each other, never against a fixed bar.** `skin-stretch.mjs` hinges
each bone independently about its own bind start, while `S9Skin.palette` uses a hierarchy and a
shortest-arc rotation, so its absolute numbers run **harsher** than the game's. Its ⛔ TEARS flag
fires above 3× and is calibrated for the imported family; every row above is fine.

⚑ **They bake correctly only BECAUSE of `.skn` v2**, which ships the bind skeleton inside the file.
Their measured shoulder lines are 0.76–0.78 of body height, not the canonical 0.80, so a v1 bake
against the hard-coded table would have torn them exactly like `ronin` did (56.6× → 8.1× once v2
landed). Every one of the seven is v2 and carries its own 11-bone bind.

### Verified on screen, not just in a bake

Headless: node http server → playwright-core → chromium with
`--use-gl=angle --use-angle=swiftshader`, driving `section9-classic.html`'s **real lobby** (8
players, so a match assigns all seven), then `__s9._bot`/`_place`/`_look` to park the camera in
front of each body in turn.

- all seven parse as `.skn` **v2** with their own bind, and `S9Skin.palette` poses every vertex
  **finite** — no NaN anywhere;
- posed height comes out **145–154 px** against a 150 px skeleton, i.e. the mesh lands on the
  skeleton rather than near it;
- `GLR.hasSkin()` reports all seven **uploaded to WebGL**, and seven bots are wearing them;
- each body renders a frame with no console errors.

⚑ One thing that only a headless run finds: `S9Skin.load()` **memoises per name and only fires

loaded fine. Parse checks and game checks now run on separate pages.

⚠ Judge **layout** from these screenshots and never colour: this container's screenshot path

## The skins — `skins.json`

A "skin" here is exactly what one draw call in this engine can express: **one tint, one `uMat` id
from `js/ronin3d.js`, one emissive amount, and optionally one tiling map** for the triplanar
sampler in `js/dogfight-gl.js`. Nothing in it needs a renderer change. A skin that required a
feature the renderers do not have would be a wish, not an asset.

17 skins in four lineage groups, plus the three palettes they are drawn from.

### The palettes, and where each number came from

| palette | provenance |
| --- | --- |
| `nouns` | **Exact.** Lifted from `packages/nouns-assets/src/image-data.json` in `nounsDAO/nouns-monorepo` — the same 239-entry table the on-chain descriptor renders from. `NounsDescriptor.sol` carries the CC0 1.0 legalcode hash as a `bytes32` constant, which is the strongest licence artefact in the whole dossier: it is as permanent as the art. |
| `xcopy` | **Measured**, not remembered. Five works fetched from the artist's own CDN and analysed; the files were not retained and are not in this repo. |
| `smowl` | **Measured** from seven SMOWLz tokens pulled over IPFS via the contract's own `tokenURI`. Same — analysed, not retained. |

### The three findings that actually shaped the set

1. **XCOPY: black is the substrate, not the shadow.** 39–71% of every frame measured at or near
   `#000000`, and exact `#000000` is the single most common value in four of the five works.
2. **XCOPY: white is absent — not rare, absent.** Near-white measured **0.00%** in all five.
   Highlights are chromatic, never neutral. ⚑ This is the one that fights the engine: additive
   bloom clips to white by default, which is exactly the look this palette does not have. Pair
   these skins with `GfxPost`'s highlight rolloff (`knee`, already measured at 0.94).
3. **Darkfarms: black is the edge, not the ground.** 21.4% of every SMOWLz token is pure-black
   keyline around flat candy fills, with one saturated accent to stop the pastels going soft.

Findings 1 and 3 are opposite uses of the same colour, and **both are in the set** — `void`/`burn`
on one side, `cel_*` on the other. That contrast is the most useful thing the study produced.

Full per-work numbers are in [`docs/CC0-SOURCES.md`](../../docs/CC0-SOURCES.md).

## The FX tiles — `tex/`

Seven 256×256 seamless maps, all generated in `scripts/build-cc0.mjs` by a dependency-free PNG
encoder over Node's own zlib.

| tile | lineage | notes |
| --- | --- | --- |
| `fx_scanline` | XCOPY | Duty cycle drifts with a periodic ramp — a CRT line is not a stripe, and the gap does as much work as the bar. |
| `fx_glitch` | XCOPY | Wrapping-lattice noise in bands, a minority shifted by a quantised amount and clipped to 1-bit. |
| `fx_dither` | Anonymice | Pure 8×8 Bayer ramp. Every pixel is 0 or 255; the tone is entirely the pattern's doing. Shares its matrix with `prop_dither`, so the prop and the texture are one pattern rather than two that resemble each other. |
| `fx_halftone` | Blitmap | Dots on a 16 px lattice with a periodic radius ramp. Where dither quantises the pixel, halftone quantises the cell. |
| `fx_keyline` | Darkfarms | The measured SMOWLz rule made literal: flat candy cells ringed by heavy pure-black keylines, one saturated accent seeded per cell, plus interior outlines — SMOWLz outlines interior shapes too, and that is what stops flat fills reading as wallpaper. |
| `fx_grid` | Nouns | The lattice as a surface: 16 px cells, 2 px grout, flat fills from the real Nouns ink/slate/ash/bone ramp. |
| `fx_rule` | Loot | A list surface — black field, white rules, a margin, and **no text**. Shipping lorem ipsum would miss the point twice: artistically, because withholding the art is the move, and legally, because the item names are the authored part. |

`tex/_contact.png` shows all seven, each tiled 2×2, box-averaged.

**Every tile is verified to tile.** They are bound with `gl.REPEAT` and sampled triplanar, so a
discontinuity at the wrap is not one seam — it is a grid of them welded to the model, invisible in
a directory listing and obvious in the game. The build measures the step across the wrap against
the largest step the pattern makes internally, and the checker itself is run against a negative
control (a linear ramp) that it must reject, so a threshold loosened in anger cannot quietly turn
the check off.

## Previews — `preview/`

Rendered with Cycles on CPU by `scripts/blender/build-cc0-preview.py`, which **re-imports the
shipped `.glb` files** rather than re-running the builders. Rendering from the build functions
would only prove the build functions render; importing the artefact proves the artefact.

| sheet | shows |
| --- | --- |
| `props.png` | all nine props and environment pieces, 3×3 |
| `bodies.png` | the three fighter silhouettes side by side |
| `hero.png` | `prop_slice`, `prop_dither` and `prop_totem` close, to judge surface rather than silhouette |

**The lighting is part of the study, not dressing.** A black world, a hot magenta key at H≈335, a
cyan fill at H≈185, a steel rim — and no white light anywhere, because near-white measured 0.00%
across the works this palette came from. The view transform is `Standard`, not Filmic or AgX:
both of those desaturate as they compress, which renders `#f80070` as dusty rose and would make
the preview contradict the finding it exists to illustrate.

⚠ The assets themselves carry **no materials and no UVs** — `kit.export_glb` strips them on
purpose, because the renderers colour geometry per draw call and a baked material would be dead
weight and one more thing to licence-clear. Every colour in these previews is supplied by the
preview script from `skins.json`.

## Rebuilding

```
npm run cc0                 # geometry + the seven .skn v2 bodies + textures + skins.json
npm run cc0 -- --tex        # textures + skins.json only — no Blender needed
npm run cc0 -- --no-skin    # geometry + textures, leaving models/*.skn alone
npm run cc0 -- --preview    # …and the Cycles sheets (~4 min on CPU)
```

The build asserts, rather than hopes:

- **every prop name** is present — `js/dogfight-gl.js` looks props up by name and fails *open*, so
  a missing one ships as silently-absent geometry that looks exactly like "the update didn't ship"
- **every one of the 15 body part names** is present, and no extras — the rig matches by name, so
  a stray object lands on a joint
- **soles at exactly z=0, crown at exactly z=1.0** — `registerModel()` derives scale from total
  height and then places parts at joints expressed as fractions of it, so one vertex poking above
  the crown shifts every joint below it. This assertion has already caught a real defect: jitter
  on the `lump` head put the crown at 1.001325.
- **every texture tiles**, with the checker self-tested against a control it must reject
- **every skin's `tex` reference resolves** to a map that was actually written
- **every baked `.skn` is the right LENGTH** — 296 bytes of header + bone table, then exactly 56
  per vertex. A `.skn` that is off by one bone table does not throw anywhere in this repo; it
  silently reads bones as vertices, which is precisely the bug `js/ronin.js` had. Cross-checking
  the byte count against the vertex count costs one line and catches the whole class.

### ⚠ Part names: do not "tidy" these to match `models/README.md`

`models/README.md` documents `arm_f_upper` / `arm_f_lower` / `arm_b_upper` / `arm_b_lower`. Tested
against the actual `JOINTMAP` in `js/ronin3d.js`, **three of those four land on the front
shoulder**:

```
arm_f_upper → armF0 ✓      arm_b_upper → armF0 ✗
arm_f_lower → armF0 ✗      arm_b_lower → armF0 ✗
```

The front-arm rule is `/(arm|shoulder|bicep).*(f|front|r|right).*(up|upper)?/` and the
`(f|front|r|right)` alternation matches a bare `r` — which both "upper" and "lower" contain. A
model authored to the README fights with both forearms and its back upper arm welded to one
shoulder. `ronin3d.js` and `models/README.md` are owned elsewhere, so this set routes around the
trap with names verified against the real map:

```
head · chest · pelvis
shoulder_f · elbow_f · hand_f      shoulder_b · elbow_b · hand_b
thigh_f · shin_f · foot_f          thigh_b · shin_b · foot_b
```

## Cleared but not yet used

`docs/CC0-SOURCES.md` grades **Poly Haven** (HDRIs, textures, models), **ambientCG** (PBR material
sets) and **Kenney.nl** (game assets) as VERIFIED evidence-class A — each states CC0 on a page
whose only job is to state it. Nothing here uses them, because this set is *generated geometry*
and those are *supplied files*, and the generated set had to come first to prove the pipeline.

They are the obvious next step and the highest-value one. A Poly Haven HDRI would do more for how
these assets look than another prop would: image-based lighting is the one thing our renderers do
not have, and it is the largest single contributor to perceived fidelity.

If any of those files are ever committed, the standing rule applies — **record the provenance
beside them**, in this file, per asset.
