# Blender + texturing pipeline — what we can use, and what runs where

A survey of the tooling handed over for "blender and games", checked rather than assumed:
every licence below was read from the project's own licence file or its repository metadata.

**The one rule this repo already has** (CLAUDE.md): *only commit geometry the artist owns or that
is clearly licensed for commercial/NFT use.* That is the artist's own standing rule, and it is the
only filter applied here. Nothing below is a judgement about the projects — several are excellent
and are simply missing a licence file, which is extremely common and easily fixed by asking.

---

## The split that actually matters: what runs HERE vs on the artist's machine

This container has **Blender at `/usr/bin/blender`** and **no NVIDIA GPU** (`nvidia-smi` absent).
So the line falls cleanly:

| | runs in this repo's automation | needs the artist's machine |
| --- | --- | --- |
| Blender **scripting** (`scripts/blender/*.py`, `npm run craft`) | ✅ already does | |
| Mesh conversion (`npm run fbx`, `npm run level`) | ✅ dependency-free, our own code | |
| **Diffusion texturing** (StableGen, Dream Textures, texture-diffusion) | ❌ no CUDA, needs ComfyUI + 7–33 GB of weights | ✅ |

That is not a small caveat. All three AI-texturing addons are **artist-machine tools**: they can
produce texture maps that get committed here as ordinary PNGs, but the generation step will never
be part of a headless run in this environment.

## Texturing tools

### StableGen — <https://github.com/sakalond/StableGen>
Blender addon. Multi-view projection texturing of a whole scene from text or reference images
(SDXL / FLUX.1-dev / Qwen Image Edit), plus TRELLIS.2 image-to-3D.
**Licence: GPL-3.0** for the addon.
**Requires:** Blender 4.2–4.5 or 5.1+ (⚠ *not* 5.0), a separate ComfyUI backend, NVIDIA CUDA GPU
(8 GB VRAM min, 16 GB+ for FLUX), and a 7.3–33 GB model download.

⚑ **One real trap.** The **TRELLIS.2 image-to-3D path** depends on NVIDIA `nvdiffrast` /
`nvdiffrec`, which are licensed for **research or evaluation only**. The GPL-3.0 on the addon does
not extend to those. The scene-texturing features do not go through it — so the practical guidance
is: use the **texturing** side, avoid the **image-to-3D** side, for anything that ships.

### Dream Textures — <https://github.com/carson-katri/dream-textures>
Blender addon. Seamless texture generation, depth-to-image projection onto scenes, inpainting,
upscaling. **Licence: GPL-3.0.** Lighter than StableGen — >4 GB VRAM, CUDA or Apple Silicon, and a
cloud option for machines that cannot run it locally. **The most approachable of the three.**

### texture-diffusion — <https://github.com/Shaamallow/texture-diffusion>
Blender addon, Blender 4.2+. Depth-ControlNet texture generation with UV projection and
multi-texture shading. **Licence: AGPL-3.0.** Also needs a separate ComfyUI plus the IPAdapter Plus
extension and depth ControlNet models.

> ⚑ **All three licences apply to the ADDON, not to the images you make with it.** Textures
> generated by any of them are ordinary asset files as far as this repo is concerned — the GPL/AGPL
> does not reach through into them, because we would be *using* the tool, not distributing it.

## Reference / assets

### Photorealistic Materials and Textures in Blender Cycles — <https://github.com/PacktPublishing/Photorealistic-Materials-and-Textures-in-Blender-Cycles>
**Licence: MIT** — permissive, commercial use fine, keep the notice.
Contains `.blend` files across 11 chapters **and real PBR texture maps** — albedo, normal,
roughness, alpha — for carbon fibre, leather, brick, grass, wood.

⚑ **This is the highest-value item on the list for the game right now.** `js/s9pc-world.js`
generates all of its albedo/normal/gloss maps procedurally on a canvas, which is why the arenas
read as flat coloured fields; real scanned-quality maps are a straight upgrade with no runtime cost
and no GPU anywhere in the loop.
⚠ Before committing any of it, confirm the *asset* provenance, not just the repo licence. Publisher
repos routinely carry MIT on the **code** while the book's media came from elsewhere. Check per file.

### Magnum 460 — <https://github.com/TheGoodFella/magnum460Blend>
**Licence: CC0 1.0**, stated in the repo's own `LICENSE.txt` (read directly).
✅ **IN THE REPO** as `models/weapons/magnum460.glb` — 2,120 tris, 66 KB, converted by our own
`scripts/fbx2glb.mjs`. Credited in `CREDITS.md`. See below for what it taught the converter.

### blenderWeaponCreator — <https://github.com/DAM001/blenderWeaponCreator>
Modular weapon-assembly addon (bases, barrels, scopes, magazines → FBX + generated icons),
Blender 4.0+. Ships **both** the addon scripts and `.blend` component models.
⛔ **No licence file** (checked: 404). Under GitHub's own terms, code without a licence is
all-rights-reserved by default, so **its models cannot be committed here** under this repo's rule.
The *approach* — modular parts assembled procedurally — is uncontroversial and is essentially what
`scripts/blender/build-craft.py` already does for the dogfight craft. **Worth asking the author for
a licence**; it is a friendly request and costs nothing.

### DanielKlas/3D-Models — <https://github.com/DanielKlas/3D-Models>
`.blend` files: Remington rifle, Nagant revolver, a pistol, a gas mask.
⛔ **No licence file** (checked: 404), no stated terms in the README. Same position as above —
cannot be committed here as-is, and worth simply asking.

## What this taught the converter

`scripts/fbx2glb.mjs` gained **`--drop` / `--only`** (comma-separated, case-insensitive substring
match on the FBX object name) while bringing the Magnum in:

```sh
node scripts/fbx2glb.mjs Magnum460.fbx models/weapons/magnum460.glb --drop Plane
```

The source carried a **3721 × 4710 backdrop `Plane`** alongside a ~60-unit revolver. Two triangles,
and it would have broken the asset silently: `fitWeapon()` in `js/s9pc-app.js` scales a weapon by
`0.86 / longest bounding-box axis`, so the plane would have shrunk the revolver to a speck, and the
cause would have been in a file nobody would think to open. 43/43 FBX tests still pass.

⚠ Filtering matches the **FBX object name**, and CLAUDE.md already records that those names lie —
one Mixamo export keeps an entire armoured body inside an object called `…_Sword`. Always run
`--list` and read the per-part bounds before filtering on a name.

## Next, in the order worth doing

1. **Real texture maps into the arenas.** Swap `s9pc-world.js`'s procedural canvas maps for
   scanned-quality albedo/normal/roughness. Biggest visible gain, no GPU, no new runtime cost.
   Gate on the per-file provenance check above.
2. **Per-weapon models.** `loadWeapon()` currently loads one GLB (`m4a1.glb`) and every weapon
   draws it — the pistol, the shotgun and the sniper are all an M4. The Magnum is in and converted;
   wiring it needs `WEAPONS[i].model` plus a viewmodel swap on `switchWeapon`, which is a real
   change to make deliberately rather than as a side effect.
3. **Dream Textures on the artist's machine** for the hero-card and arena material passes — the
   least setup of the three, and the only one with a cloud path for a machine without the GPU.
